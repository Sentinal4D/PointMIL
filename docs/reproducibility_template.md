# Reproducibility

This document lists the results obtained with this code: the released checkpoints
evaluated with it, and models re-trained with it, next to the published values. It is
generated by `scripts/make_reproducibility.py`.

## Evaluation protocol

1. **Splits.** IntrA and RBC use the five folds in `splits/intra/` and `splits/rbc/`,
   ATLAS-1 the train/validation/test split in `splits/atlas1/split0.csv`, and
   ModelNet40 and ScanObjectNN their official train/test splits.
2. **Checkpoint selection.** `train.val_split` sets the split used for checkpoint
   selection and early stopping (`test` in the provided configs; `holdout`, or
   `validation` for ATLAS-1, selects on held-out training data instead). `summary.json`
   records the test metrics of the selected checkpoint (`test_best`), of the last epoch
   (`test_last`) and the best values reached during training (`highest_val`).
3. **Point sampling at test time.** IntrA and RBC clouds are subsampled to 1024 random
   points (seed 42), ATLAS-1 clouds by farthest point sampling from their first point,
   ModelNet40 clouds keep their first 1024 points and ScanObjectNN uses a cached
   farthest point sample. Re-evaluating an IntrA or RBC checkpoint therefore varies by a
   few tenths of a percent.
4. **Interpretability.** The Table 1, Supp. Table 3 and Fig. 6 metrics (AOPCR, NDCG@n)
   are computed on the 116 annotated aneurysm segments for each fold's model
   (`--split annotated`), scoring the aneurysm class (class 1).
5. **Numerical equivalence of the port.** All ported modules load the original
   weights and reproduce the original forward pass, and one training step through
   OpenPoints and through this code gives the same parameters (`tests/equivalence`).
   The fused CurveNet-MIL model was rebuilt from the layout of its trained weights; its
   re-evaluated metrics below are the check.
6. **Head layouts.** The release code supports every layout found in the released
   checkpoints: the instance-classifier variants of the IntrA, RBC and ModelNet40 models
   (including features raised from d to 4d before conjunctive pooling and a narrowing
   d, d/2, d/4 classifier), two OpenPoints instance heads, and two attention-pooling bag
   classifiers (an MLP on the concatenated attention-weighted mean and max, or one linear
   layer on the mean, used by the ATLAS-1 DGCNN, PointNet and PointMLPElite and the
   ScanObjectNN PointMLPElite models). Layouts are read from the checkpoint where the
   tensor shapes determine them and are written in the configs where they do not
   (`attention_classifier`).
7. **RBC point clouds.** The RBC point clouds are the marching-cubes vertices (with
   normals) of the public 3D masks; `scripts/prepare_rbc.py` recreates them from the masks
   (byte-identical for all 825 cells).
8. **Not covered here.** The ModelNet40 CurveNet dagger and PointMLPElite dagger rows
   were produced with the CurveNet and PointMLP repositories and are not re-evaluated.

## Models trained with this code

Every run below used `scripts/train.py` with the config of the same name, seed 42, on
one Quadro RTX 6000 shared with other jobs (train time is wall clock on that GPU).
"Test (best ckpt)" is the test metric of the selected checkpoint and "max over epochs"
the best value reached during training. Each model's exact training config is stored
with it on the Hub. AOPCR / NDCG@n are the Table 1 metrics (contextual attention
k = 12, all 116 annotated segments).

The re-trained IntrA PointMIL(Trans.) conjunctive model reaches 96.2 / 96.1 mACC / F1
over 5 folds as the best values during training, 93.6 / 94.2 for the selected
checkpoints, and AOPCR 17.1 / NDCG@n 0.602, in line with the released checkpoints
evaluated by the same code (93.5 / 94.9).

The ATLAS-1 PointMIL(DGCNN) instance model re-trained with the OpenPoints recipe reaches
83.2 / 82.5 / 82.5 mACC / oACC / F1 on the test cells, the same as the released
checkpoint evaluated by this code (83.1 / 82.5 / 82.4).

The RBC DGCNN and RBC Transformer additive rows add the folds that had no released
checkpoint (DGCNN: additive fold 4, attention folds 3 and 4, conjunctive fold 4,
instance folds 3 and 4; Transformer additive fold 0), so that every RBC model has 5
folds.

The PointMLPElite rows on IntrA and RBC are 5-fold runs trained with an earlier version
of the configs (100 epochs for every head, weight decay on all parameters); the current
configs use the schedules of the original runs and the OpenPoints weight-decay groups.

## Determinism

`seed_everything` seeds Python, NumPy and PyTorch, sets `cudnn.deterministic`, and
`DataLoader` workers are seeded. Remaining sources of non-determinism on GPU:
`torch.topk` tie-breaking in the k-NN graphs (identical coordinates), the
scatter-based gathers of the DGCNN edge features, and cuDNN kernels for 1x1
convolutions when deterministic algorithms are unavailable. Re-running a config with
the same seed on the same GPU reproduces the training curve closely but not bit for bit.

Measured: two runs of `configs/smoke/synthetic_transformer_conjunctive.yaml` with
`--seed 42 --device cpu` for 3 epochs produced identical per-epoch accuracies and
F1, training and validation losses that agree to 8 significant digits, and final weights
that differ by at most 8.3e-4 (absolute). On CPU the residual difference comes from the
summation order of multi-threaded BLAS reductions, not from the random number streams
(Python, NumPy, PyTorch and the `DataLoader` workers are all seeded).
